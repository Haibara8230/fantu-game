# 开发路线

## 整体方向
同一个修仙世界持续运转。玩家在几百年的世界跨度里，通过修炼、探索和交际度过一段修仙人生；剧情由地图、日历和条件共同触发。玩家的游戏过程始终处在同一条世界时间线上。参考《觅长生》的交互方式：只有交互行为和赶路推进日期，查看菜单与整理界面不消耗时间。

开发节奏：先完成并精细打磨约 5 小时的样板流程，以它确定画面、手感、节奏和内容密度的标准，之后按同一标准逐段扩展。宁可放慢，也要把细节做足。

## 已确定的决定
| 项目 | 决定 |
|---|---|
| 引擎 | Godot 4.7.2 / GDScript，Windows 单机；确认兼容后再升级 |
| 世界跨度 | 几百年 |
| 时间 | 统一按日；固定每月 30 天、每年 12 个月（360 天） |
| 单周目时长 | 40–80 小时，试玩后校准 |
| 世界大事 | 大部分固定；少数大事在玩家达到一定实力并满足条件时可以改变 |
| 归宿 | 多种结局，规则保持简单 |
| 存档 | 只有自由读档（自动存档 + 手动存档），不做铁血模式 |
| NPC | 手写核心人物 + 按模板生成的人口 |
| 地图与战斗 | 节点式大地图 + 二级场景；沿用 2D 回合制斗法 |
| 功法与装备 | 数量充足，组合生成，让大多数 NPC 与玩家的配置不重复 |
| 特效 | 同一特效家族可共享素材；不同品阶必须明显区分，越强越华丽 |

详细数值与规则见 `docs/DESIGN_BASELINE.md`。

## 前 5 小时样板范围
- 游戏内约 10–20 年：从入门炼气，到筑基突破，以及突破后的第一段经历。
- 区域：青云山、云溪坊市、落霞谷，再加 3–5 个新节点。
- 人物：8–12 个核心 NPC，加区域内的生成人口。
- 剧情：3–5 条交织的事件线；一种周期活动（坊市拍卖或宗门小比）。
- 可以改变的大事：妖蟒之乱。默认情况下妖蟒会在某年封锁落霞谷若干年；玩家若在期限前筑基并满足条件，可以提前平定。

## 长期贯穿的工作
- **功法、装备与特效**：功法和装备由“基础模板 × 品阶 × 属性 × 词条”组合生成；特效按家族共享素材，按品阶叠加层次。规则见设计基线。
- **测试**：全部在后台运行（--headless）。重点：时间推进等价性、存档迁移样例、随机时间点存读档往返、几百年长时间模拟、内容静态检查、性能预算。
- **平衡**：后台自动玩家批量模拟，统计各境界耗时与资源曲线，辅助试玩校准。
- **美术与音效**：沿用二维手绘、清晰线稿、平涂与克制阴影的风格。每个新地区、人物、功法都带完整表现，不让占位素材进入完成态。

## 工程原则
- 规则、数据定义与表现分离；内容引用稳定 ID，存档不保存 UI 节点。
- 时间只能通过统一的推进入口改变。
- 存档带版本号；结构变化时编写迁移，先迁移再校验，不直接删除旧存档。每个旧版本保留一份样例存档作为测试素材。
- 随机数按用途分流，世界模拟不得打乱战斗结果。
- 功法和敌人数值使用独立配置，规则保持单一来源。
- 避免把系统提前堆成空框架：每个系统都要有实际内容在用。
