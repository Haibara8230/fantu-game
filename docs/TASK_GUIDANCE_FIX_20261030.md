# 任务提示与原地连续触发修复

2026-10-30。针对“任务不知道在哪里触发”和“同地点连续任务要离开再回来”的反馈。

## 玩家现在看到的变化

- 目标与剧情页共用同一套提示：地图区域、具体地点、人物所在建筑、左侧「此地人物」入口、人物姓名与交谈选项。
- 材料交付显示持有／所需数量及已有来源提示；计数任务显示当前步骤开始后的进度。
- 等待步骤显示预计日期和剩余时间；未达到开始要求的已知任务显示实际境界等条件，不再只写“时机未到”或从目标里消失。
- 与当前步骤相关的地点事件显示事件名、时间窗口、尚缺的触发条件及选项要求。
- 主动选择暂缓后，任务页提供「继续此事」按钮；在正确地点可立即重新打开抉择，不消耗一天或旅费。
- 委托页补回完整委托描述，并写明回哪个城市、哪个告示处交付。

这些提示从真实步骤、事件及人物交互规则派生。阅读任务不会结算进度、给予奖励或推进时间。

## 两处触发原因

原来的动作结束流程先检查地点事件，再更新剧情步骤。前一事件推进的步骤在地点扫描之后才生效，所以后续地点事件常要等另一次抵达才会出现。现在统一在动作结束、抉择结束和必要的剧情变化后，结算剧情与当前地点事件，直到稳定或遇到需要玩家处理的事件。

另外，故事进度上的 `asked` 记录原本没有随步骤结束清除。它本来用于“今天暂缓的这一问不要立刻再问”，却也挡住了同一天的下一问。现在完成／跳过步骤时清除该记录，仍保留当前步骤主动暂缓的含义。

一次结算保留已访问事件和事件分组，防止重复奖励；已有抉择、斗法、拍卖和突破仪式保持控制权。普通装备或拍卖操作没有剧情变化时，不额外执行到达地点的附带行为。

## 兼容与验证

没有新增必须保存的字段、改动存档版本或重置任务进度。既有步骤与事件 ID 保留；旧记录中的 `asked` 仍可读取，暂缓的当前抉择可以用新按钮重新打开。

`tests/story_flow_smoke.gd` 验证真实入世的“城门 → 集会 → 拍卖”原地连续链、未来日期等待、同日两问、主动暂缓与重开、奖励不重复、活动不被抢占、存档往返及提示只读；同时遍历 169 个已发布的任务／等待步骤检查提示生成。

`tests/ui_smoke.gd` 新增真实界面操作：剧情与目标页显示交付入口和缺口，点击「继续此事」重开听潮剑修复事件，再次暂缓后按钮仍可使用。

全部自动启动使用 `--headless`，日志在 `.tmp/task_*.log`。没有打开可见游戏窗口，未做人工画面验收。

最终专项结果：任务与提示 202、界面 267、剧情 134、体验 111、筑基 51、结丹 62、元婴 77、化神 56，共 960 项通过，无脚本错误。界面新增 6 项检查全部通过。
