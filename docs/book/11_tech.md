# 第十一章 技术与工程

本章写给要改这款游戏的人：代码与数据怎样组织、时间与随机怎样保证可复现、存档怎样迁移与校验、测试怎样跑、后台工具做什么，以及截图时保护玩家存档的措施。

---

## 11.1 技术栈

- **引擎**：Godot 4.7.2，GDScript。仓库里带着便携版 Godot（`.tools/godot/`）。
- **平台**：Windows 单机，本地存档。
- **规模**：`scripts/core/` 与 `scripts/ui/` 共约六十个脚本，连同测试与工具约两万一千行 GDScript；`data/` 下二十六个 JSON 配置。
- **启动脚本**：

| 脚本 | 作用 |
|---|---|
| `play.cmd` | 打开游戏 |
| `edit.cmd` | 打开 Godot 编辑器 |
| `check.cmd` | 在后台跑全部测试 |
| `preview_sects.cmd` | 门派试演 |
| `preview_art.cmd` | 美术预览 |

## 11.4 时间

- 世界时间只有一个来源：`world.day`。所有行为都通过 `advance_days` 消耗时间，不允许在别处直接改日期。
- 推进时按日期顺序处理整段区间内到期的所有事项：日期事件、提醒、过期、委托与传音的期限、人物的生老病死、寿元的提醒与终结，每件事记在它实际发生的那一天。
- 闭关与停留可被提醒或寿元告急打断，只结算已经过去的天数；赶路与整顿不可打断。
- **长短一致**是硬性要求，测试里直接比对：一次长闭关与多次短闭关（中间不做别的事）的修为、事件、世界状态完全一致；一次长住与多次短住遇见的人相同。为此：
  - 修为按日累计，余数以百分之一的精度留到下一次；
  - 心神只按「上次闭关结束时的疲惫」与「此后过去的日子」算；
  - 人物的位置由日期直接算出；
  - 人口的位置索引只在有人去世或到来时重建。

## 11.5 随机

- 随机数按用途分流：**斗法**流（`combat_rng`）与**世界**流（`world_rng`）。世界侧消耗随机数不会改变斗法结果，反之亦然。
- 许多「读档不变」的结果不用流，而是由世界种子与键直接算：`session.seeded_roll(parts)` 用 `hash([seed] + parts)` 给一个新的随机数生成器做种子，取第一个值。坊市行情、洞府宝物、拍卖心理价、炼器词条、炼丹结果、委托、求助、主动来往都这样算。
- 不直接取字符串的 hash：Godot 的字符串 hash 在键的末尾只差一个字时几乎不变（2026-10-14 发现并修正）。
- 生成人口完全是世界种子、席位与世代的纯函数，不入存档。
- 功法与法宝完全由 id 推算，同一 id 永远得到同一结果。

## 11.6 内容静态检查

`content.gd` 在加载数据时运行一整套检查，发现问题就拒绝启动并写明原因：

- 未知的地点、标记、物品、人物、事件、剧情、对手；
- 时间窗口颠倒；
- 抉择事件没有无条件的选项（玩家会被卡住）；
- 关键事件只有一条入场途径；
- 提醒或过期用在周期事件上；
- 隐藏地点没有揭示的途径；
- 每个境界、小阶段的字段齐全且递增；
- 特效的逐阶递增项严格递增，`unlocks` 里的项不回落且至少在一阶出现，每个门派都有专属层；
- 宗门职司、兑换、捐献的配置有效；
- 炼器材料、拍卖拍品池、石室的连接与宝物有效；
- 道贺的种类（`CONGRATS`）在人物里写对；
- 场景的行为都是已知的行为。

## 11.7 存档

### 11.7.1 文件

- 自动存档 `saves/auto/`，手动存档 `saves/manual/`，在玩家的用户目录下。
- 每种各保留两代，最新一代损坏时读取前一代。
- 存档是 JSON，记版本号、会话的全部状态（玩家、世界、斗法、拍卖、待决事件、结局）。生成人口、功法法宝的定义、世界种子能推算的东西都不存。
- 一整局玩到第 480 年飞升，存档约 106 KB，读档约 15 毫秒。

### 11.7.2 版本与迁移

当前是**第 15 版**。迁移链逐版本执行（v1→v2→…→v15），**先迁移再校验**；校验从配置计算上限，不写死常量。

| 版本 | 加入 |
|---|---|
| 2 | 时间从按月改为按日（`world.day`）、出生日、世界标记、结构化的编年史、斗法与世界两条随机流、宗门传承 |
| 3 | 事件进度、人物、物品、按日修炼、待决与结局状态 |
| 4 | 多段行程、按行为的冷却 |
| 5 | 好感（0–200）、按人的状态 |
| 6 | 灵根与小阶段 |
| 7 | 灵草与丹药并入物品堆叠 |
| 8 | 习得的功法、栏位与法宝 |
| 9 | 委托与传闻 |
| 10 | 活的生成人口（「g:<席位>:<世代>」） |
| 11 | 心神、历练与瓶颈 |
| 12 | 剧情、传音、事迹、教学卡 |
| 13 | 天赋（旧存档按世界种子补抽一组，记一笔「天赋苏醒」；旧世界的人物命数不变） |
| 14 | 宗门身份与贡献（旧存档从外门弟子开始，已交付的委托每件折 15 点贡献） |
| 15 | 丹方、炼丹熟练、丹毒与灵田（旧存档不会任何丹方，凝气丹剩下的服用间隔折成同样久的丹毒） |

第 15 版之后加的东西（职司、拍卖、洞府、神识、金丹品级、延寿、道侣弟子结拜、行情、炼器……）都是**可选字段**：有默认值，读档时校验，不合法的整份存档拒绝读入，不认识的东西（已删除的剧情、已故去的人）丢弃。这样就不必为每个小功能升版本，旧存档照样能读。

### 11.7.3 样例存档

`tests/fixtures/` 保存每个旧版本的真实样例存档（v1 的新开局、完成态、斗法中；v2 的斗法、筑基斩蟒、坊市；v3 的请柬、待决抉择、落霞谷……一直到 v14 的凝气丹间隔）。迁移测试必须覆盖它们。

## 11.8 测试

### 11.8.1 怎样跑

`check.cmd` 先在后台导入资源，然后依次运行十六个测试，每个都用 `--headless`，不打开任何可见的窗口：

```
core_smoke world_smoke events_smoke region_smoke growth_smoke arsenal_smoke
society_smoke story_smoke talent_smoke bonds_smoke art_smoke ui_smoke
presentation_smoke sect_smoke alchemy_smoke cave_smoke
```

- 每个测试有 180 秒的外层时限（导入 600 秒），超时就杀掉整个进程树并记 `TIMEOUT`。这是因为卡住的 Godot 永远走不到测试自己的计时器。
- 退出码不为 0、超时、或输出里有 `SCRIPT ERROR`，都算失败——Godot 在脚本出错后还会继续运行，只看退出码会漏掉。

### 11.8.3 测试的规矩

- 用户明确要求后台测试：所有自动测试都用 `--headless`，不打开、不聚焦可见的游戏或编辑器窗口。
- 不启动可见的图形测试，除非用户明确要求。
- 检查输出里的脚本错误，而不只是退出码。
- 新加的存档字段必须有默认值与校验，测试要覆盖旧存档读入。

## 11.9 后台工具

| 工具 | 作用 |
|---|---|
| `tools/duel_sim.gd` | 在后台按「速战」的简单出法、用五种灵根批量对打，打印各对手的回合数、胜率与剩余气血，以及切磋与五宗论道的结果；用来校准对手数值（第四章 4.8.1 的表就是它跑出来的） |
| `tools/long_play.gd` | 在后台玩完一整局：闭关、买丹、突破、只在必要时出门，记录存档大小、读档耗时与最慢的一次行动。实测：第 480 年化神圆满飞升，存档 106 KB，读档 15 毫秒，最慢一次行动 77 毫秒 |
| `tools/story_report.gd` | 剧情检查报告（分析在 `tools/story_check.gd`）：只读数据与脚本文本，列出每条剧情的入口、各步的开始条件与完成方式、奖励、留下的旗标与谁读取它，剧情要用的物品及其来源，全部旗标的设置与读取。找出「错误」（没人能开启的剧情、完成不了的步骤、永远不成立的条件、引用不存在的人物物品剧情步骤、没有来源的物品）与「提醒」（可反复领取的奖励、步骤与推进它的交互各发一份、设置了没人读的旗标）。报告写到 `.tmp/story_report.md`，有错误时退出码为 1；`tests/content_smoke.gd` 也跑这项检查，有错误即失败，并用埋入故障的数据副本验证每一类都能查出 |
| `tools/capture.ps1` + `capture_screens.gd` | 截取各页面的截图，用来检查排版（只看 1920×1080 与 2560×1440 两种分辨率） |

### 11.9.1 截图的安全措施

截图必须打开真正的游戏窗口（无头模式没有画面），所以要特别小心不碰玩家的东西：

- 截图从项目的临时副本运行，用它自己的用户目录（以 `fantu_capture` 结尾）；
- 写给 Godot 的 `override.cfg` 不带 BOM（Windows PowerShell 5.1 默认带 BOM，会让 Godot 忽略这个文件，转而写进玩家的用户目录——2026-10-14 出过一次这样的事故，覆盖了玩家的自动存档与教学记录，之后修正）；
- 窗口放在屏幕外（`--position -9000,-9000`），不抢焦点；
- `capture_screens.gd` 在用户目录不以 `fantu_capture` 结尾时拒绝运行；
- 每次截图后核对玩家的用户目录没有新文件。
