# 与《觅长生》的体验差异及修改计划：斗法优先

第二轮状态（2026-10-23）：用户后续确认的七项改动已接入基础实现，现行功能、固定视频时间码及未完成的完全一致校准见 [第二轮实施记录](MCS_ALIGNMENT_IMPLEMENTATION_20261023.md)。下文保留第一轮调研与定稿过程；其中“无生／同／克”“未测时间码”等现状描述已有后续替代。

日期：2026-10-23。状态：第六版斗法视觉样张已获用户确认（「就按现在这样」），第一轮游戏实现已接入，详见 [实施记录](BATTLE_UI_V6_IMPLEMENTATION_20261023.md)；动画逐帧校准与图形体验验收尚未完成。本文中的待办不能视为全部已完成。

## 1. 用户定案，覆盖上一版建议

1. **斗法按《觅长生》的布局、操作流程和动画尽量一比一还原。**比例、槽位、配气方式、确认操作和节奏都要对照实际参考，不再以现有简化操作作为必须保留的设计。
2. **取消独立守御功能。**移除按钮、快捷键、玩家规则入口及其减伤、额外吸气效果。护盾神通、防御功法和敌方防御招式属于不同机制，继续作为神通与敌人配置存在。
3. **丹药在战前服用，开战后不能再吃丹药。**这是用户对服用时点的明确确认，不能解释成战前装槽、战中点击使用。
4. **灵气获取和使用必须有与原作对应的完整动画。**以原作实际画面校准运动路径、先后顺序、时长、停顿、光效及音效触点，不用数字跳变替代动画。
5. **本批优先交付斗法样板，再向其他界面推广。**现有人物与世界内容继续使用；自动测试只用 `--headless`，保留玩家存档，所有临时数据写项目 `.tmp/`。

上一版的“保留守御”“战中丹药面板”“中央只放回合结束”“固定六神通槽不变”均已撤销。神通槽及快捷键应随原作布局一并核对和调整。

2026-10-23 视觉定稿：用户以「就按现在这样」确认第六版。左右沿用已认可的第五版设计，中央采用第六版配气轮盘；后续制作以此为视觉基准。中央配气状态以新找到的[官方 12.14 更新公告配图](https://steamcommunity.com/games/1189490/announcements/detail/3128310340404203146?l=schinese)为依据：上沿左蓝「取消」、右橙「确定」，内部显示分组灵气、数量与关系标记，低对比度太极与八卦底纹；不再添加「施放」、技能名、费用与说明文字堆叠。「克」标记仅为视觉示意，不代表新增克制伤害规则。

## 4. 灵气交互与动画专项

### 4.1 交互状态

斗法 UI 采用明确的阶段：入场/吸气 → 等待选招 → 配气 → 确认施法/演出 → 等待下一操作 → 回合结束/消散 → 对手行动 → 下一次吸气。

- 选神通先进入配气状态，不立即扣气、造成伤害或消耗物品。
- 中央区域显示自动选出的合法支付方案。再次点击同一神通可调整自动方案，支持按属性手动换气。
- “指定五行”“同×N”“任意”的合法性由规则层统一校验。确认时重新校验余额和方案，不能由 UI 复制支付算法。
- 原作官方说明包含复用上一回该神通所用灵气组合的行为；本项目实现对应偏好，无可用组合时回退合法自动配气。
- 取消配气返还预留显示，实际库存和随机数不变。改选神通先清理旧预览，不能同时占用两份灵气。
- 中央确认、取消与结束回合按选定参考的状态切换；官方历史说明为：空格确认施法，Esc 取消或结束回合。现有空格直接结束回合的默认设计需要一并修改，旧键位配置作兼容处理。
- 消散阶段左键精确操作及右键按属性批量操作，按原作参考核对；明确显示本轮剩余需消散数量，不能超量消散或影响其他阶段。
- 五行生克关系的界面表现只展示已核实、已实现的规则。若原作对应技能机制尚未移植，列为规则差异补齐，不能画出虚假的伤害加成。

### 4.2 必须逐项对齐的动画

| 场景 | 要交付的动画与反馈 | 目前需要的补充 |
|---|---|---|
| 开场与每回合吸气 | 按原作的灵气生成/进入方式、归位顺序与数字变化播放 | 补 `draw` 的可见事件消费；起点、曲线、批次及音效用录屏测量 |
| 选择神通 | 对应灵气从右下盘移到中央八卦阵，展示选中状态 | 新增配气预览与移动演出，不提前提交战斗结果 |
| 调整或取消配气 | 对应灵气更换或返回；数量与中央方案保持一致 | 建立预留显示和实际持有量的区别，处理快速切换 |
| 确认施法 | 按参考完成灵气消耗、中央阵变化、出招与命中 | 关联已确认 `spent`，分清确认前和确认后的事件时点 |
| 神通转换/即时得气 | 新获得的属性有对应进入灵气盘的过程 | 覆盖印、聚灵、法宝、战前丹药的开场或逐回合药效，区分即时与下回合来源 |
| 回合末消散 | 被消散的属性按参考退出或消散，然后进入后续阶段 | 补 `discard` 动画与超限阶段，不能直接刷新数字后跳过 |
| 对手操作 | 对手对应的灵气与出招反馈按可见参考实现 | 与现有敌方事件兼容，不将不可见信息擅自公开 |

每个样例记录参考版本、来源、时间码、起点/终点、持续时长、间隔、曲线、透明度/缩放及声音触点。尚未测量的条目标为待校准，不能填入猜测的“原作参数”。完成标准是相同操作下画面过程可逐段对照，而不是“有动画”即可。

规则状态仍只结算一次，UI 通过事件序列回放各阶段的显示值。演出中锁定会提交结果的输入；不能让真实灵气已扣完而界面反复渲染最终值，也不能在动画回调再次扣气。取消、暂停、读档和场景销毁应能清理预览与队列。

## 5. 战前丹药专项

已确认：**战前服用，开战后禁止吃丹药**。

- 普通疗伤与恢复丹在非战斗状态服用并即时生效；开战后不可补吃。
- 为下场战斗准备的丹药，服用时消耗物品并登记待生效药力；开战时按丹药定义转为开场效果、首回合效果、整场效果或逐回合效果。
- 现有回气丹的战中即时得气不能原样保留。应调整为相应战前用途，并在物品说明中写清触发时点；丹药不允许在无战斗时把灵气加入不存在的战斗手牌。
- 药效持续到下一场、持续几回合、是否可叠加及耐药限制需要通过原版资料核对后数据化；未确认前不臆造数值，也不将所有丹药硬改成同一种效果。
- 行囊/人物状态显示已服药力与适用场次，战场仅显示效果；不新设“战前装药、战中使用”的变体。
- 所有开战入口统一接收准备状态：主动挑战、切磋、大比、秘境与路上遭遇。突然遇敌不额外赠送一个可临时服药的暂停准备阶段。
- 将战中服丹从 UI、规则入口和速战策略一起禁用；符箓不属于丹药，不能因为共用 `take_pill()` 路径就误删，需按类别拆分处理。
- 切磋、连续赛事、撤离、败北对“下一场”药力的消耗按统一规则处理并清楚告知；相关差异纳入原版核对表。
- 服药、进入战斗、结束/撤离、战斗中存读档各只处理一次物品及药效，避免读档重放药力或重复扣物。

## 6. 取消守御的完整范围

- 移除斗法按钮、默认 G 键及设置页条目，清理教学卡、操作提示与指南中的守御说明。
- 移除 `Session.defend()` 对外玩法入口及玩家独立守御规则；单纯结束回合没有减半敌方伤害和额外吸气奖励。
- 清理 `guard_orbs`、独立守御次数统计及其战后建议依赖；更新自动玩家、速战和测试，禁止通过旧函数继续取得效果。
- `guard` 同时被用作护盾神通类型、敌方防御动作与演出事件名；按用途处理，不能全局替换后连护盾神通一并破坏。
- 旧存档里的 `guarded_turns` 等字段可兼容读取或忽略；不因此拒绝读档。旧快捷键中的守御映射忽略，不影响其他绑定。
- 存档中已经产生的护盾、伤势、丹毒及既有灵气余额按各自合法状态恢复；不以删除守御为由回溯扣除玩家资源。

## 7. 实施顺序与交付

| 批次 | 内容 | 验收重点 |

| A：原作基准与核心规则 | 统一参考版本，建立操作和动画对照表；取消守御；建立战前服丹及药力生命周期 | 守御入口和奖励均不可达；战中不能服丹；旧档可读；自动策略可继续运行 |

## 8. 工程落点与验收约束

- `scripts/core/combat.gd`、`session.gd`：显式支付方案校验和确认、取消守御、禁止战中服丹；规则不依赖 UI 动画是否结束。
- `scripts/core/inventory.gd`、`data/items.json`：战前丹药、药力触发时点与提示；沿用既有丹毒验证，新增规则保持单一来源。
- `scripts/core/save_restore.gd`、`save_migration.gd`：新药力/偏好等可选字段提供默认值及校验；历史战斗余额、战中用药计数和守御记录兼容恢复，不能重复应用药效。
- `scripts/ui/battle_view.gd`、`main.gd`、`settings.gd`：按阶段组织配气、确认、键鼠和辅助面板；撤销旧守御/即时服丹交互。
- `scripts/presentation/battle_stage.gd` 及拆出的灵气演出组件：消费灵气事件并关联 UI 锚点，战场不因展开记录或动画阶段改变尺寸。
- `data/art.json` 与现有 UI/图标素材生成链路：站位、人物比例、操作盘及图标呈现。保持二维手绘风格，使用项目资源实现对照效果。
