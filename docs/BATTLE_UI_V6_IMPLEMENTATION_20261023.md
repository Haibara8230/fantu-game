# 第六版斗法界面：第一轮实现

后续更新：灵气动作已改为固定大图标和成批细光迹，配入／消耗时间码已有固定官方片源证据；生／同／克与尘沙也已接入规则，详见 [第二轮实施记录](MCS_ALIGNMENT_IMPLEMENTATION_20261023.md)。下文的第一轮参数和验证数字仅作历史记录。

## 已接入

- 满屏战场，人物脚底约在画面高度 66%、人形高度约 30%；顶端双侧状态头，底部左神通、中央配气、右五行盘。神通容量为十门，另有兵刃祭出格；兵刃额外神通超过十格时仍可从「更多」施展。
- 使用定稿提取的透明手绘底板，按定稿比例注册坐标。技能、五行图标、文字、计数和鼠标区域由游戏独立绘制；没有把整张样图铺在游戏上。提取物并非逐像素原样，需用实际预览继续比对。
- 选神通先自动配气；重复选同招可轮换自动组合。点击中央灵气退回，再点右盘补入。空格／「确定」才提交，Esc／「取消」撤回。规则层校验五行指定、「同」与「任意」费用、余额和总数；确认前不扣气或改变随机流。成功方案在本场内记忆，旧档无此字段时默认空。
- 超过留气上限，结束回合先进入消散；左键一颗，右键按属性散去仍需消散的数量。达到上限后确认，不能额外消散。默认神通键为 1–5、Q/W/E/R/T，D 祭出兵刃；旧守御映射忽略，其余合法旧键位尽量保留。
- 得气、配气、换气、取消返还、确认消耗、神通即时得气及消散逐项演出。生成修士的得气、消耗和消散也由事件驱动，计数随到达或离开更新。演出期间提交输入锁定；速战跳过中间回合演出，仅显示结局。
- 独立守御按钮、快捷键、公共规则函数、额外抽气、伤害减半和战后建议已移除。护盾神通、敌方防御、护心等宝物效果保留；历史守御字段与旧编年史可继续恢复和阅读。
- 丹药只在战前从行囊服用。疗伤丹立即生效；回气丹立即恢复灵力，并把原有额外两颗／三颗灵气改为下一场开场吸收，同类准备不能叠服。所有战斗通过共同开场处理，突然遭遇不赠送准备阶段。药力随首次开场消耗，撤离、败北和连战不返还或重复触发；保存恢复不重复扣物或得气。
- 符箓继续可在战中使用。无相袋作为原有剧情信物保留，已移除它增加战中服丹次数的效果。记录、探查、求援、布阵、群敌目标、秘术、撤离与速战保留；辅助面板覆盖场景，不挤压舞台。

## 入口、素材和参数

- 用户自行运行 [`preview_battle_v6.cmd`](../preview_battle_v6.cmd) 可打开独立斗法试演。试演的存档、设置和日志在项目 `.tmp/`，不会覆盖旅程。该入口本轮未自动启动图形窗口。
- 底板：[`dock_v6.png`](../assets/art/ui/battle/dock_v6.png)，内置 image_gen 制作；完整提示词、来源、哈希与尺寸在 [`battle_ui_v6_20261023.json`](../art_sources/battle_ui_v6_20261023.json)。状态头边框为原生 SVG。
- [`battle_presentation.json`](../data/battle_presentation.json) 保存灵气时长、弧度与尾迹参数。当前为可调初版值，**尚未声称与原作逐帧一致**；转移和消散使用项目现有轻音效，也待声画对照校准。
- 规则／准备药力／可选存档校验与表现层分开。新药力和配气字段恢复前验证，缺字段按无准备、无记忆处理；非法字段拒绝恢复且不修改当前旅程。

## 验证与边界

共验证 33 套、4521 项检查，32 套通过；余下一套只有下述既有性能预算失败。斗法专项 81 项、界面 239 项、演出 59 项均通过；具体逐套结果留在 `.tmp/battle_v6_verification.json`。重点覆盖原子支付、取消、手动换气、消散上限、符箓、护盾、旧档、战前药力、连续场次，以及 1280×720、1920×1080、2560×1440 的控件范围和抽屉不改变舞台。

全套中的五百年模拟性能预算仍有失败：现版长跨度 350ms、逐月 6542ms，未修改 Git 基线对应为 341ms、6578ms，均超过原有 5000ms 总预算。基线证据在 `.tmp/battle_v6_baseline_events.log`；未放宽阈值，当前不能宣称 `check.cmd` 全绿。

无头检查不能证明实际字形、透明边缘、人物与特效遮挡或原作动画一致。后续图形验收须由用户主动启动预览；原版录屏的时间码、轨迹、顺序和声音触点仍按 [差异计划](MICHANGSHENG_UI_GAP_PLAN_20261023.md) 补齐。中央没有虚构五行克制伤害标记。
